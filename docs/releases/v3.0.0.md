# shotkit v3.0.0

Released 2026-07-30. This release makes the audit trail checkable. Every input, prompt, and
reviewed frame is pinned by SHA-256, and a validator recomputes the hashes.

## Breaking: the output layout moved

The output tree is the public interface. Everything is now addressed by round and shot, so two
writes never land on the same path.

| v2.0.0 | v3.0.0 |
|---|---|
| `output/critique.json` | `output/critiques/round-{N}/{shot_id}.critique.json` |
| `output/prompts/{generator}.txt` | `output/prompts/round-{N}/{generator}.txt` |
| `output/prompts/revised-{generator}.txt` | `output/prompts/round-{N}/revised-{generator}.txt` |
| `output/generated/{shot_id}.png` | `output/frames/round-{N}/{shot_id}.png` |

Each run also writes `output/run.json`. It records a run id and the SHA-256 of `shots.json`,
`text-overlays.json`, and `brand-lock.snapshot.md`. Those inputs are fixed once written. The
prompt-forge appends one `rounds` entry per round, with a hash for each prompt file.

Critique schema `1.1` adds `run_id`, `round`, `created_at`, `image_sha256`, `prompt_ref`,
`prompt_sha256`, `brand_lock_sha256`, `generator`, `model_version`, `seed`, and `meta`. The
provenance fields are required and nullable. `null` means the input was not available.

## Upgrading from v2.0.0

Nothing auto-migrates. Old trees still read: the preview finds frames in `generated/` and a root
`critique.json`, the prompt validator reads flat `prompts/*.txt`, and `1.0` critiques pass with a
warning. `validate_provenance.py` fails any tree with no `run.json`, on purpose.

To move a tree by hand, edit first and hash last:

1. Move frames into `frames/round-N/` and prompts into `prompts/round-N/`.
2. Add `# Run:` and `# Round:` to each prompt header.
3. Fix `shots.json` until `validate_shots.py` passes.
4. Write `run.json` with the hashes.
5. Move the one surviving `critique.json` into `critiques/round-N/`, and run
   `visual-asset-critic` on every other frame.

Confirm with:

```bash
python ~/.claude/shotkit-tools/validate_provenance.py output/ --require-accept
```

The full steps are in "Upgrading from v2.0.0" in
[`CHANGELOG.md`](https://github.com/whystrohm/shotkit/blob/main/CHANGELOG.md).

## Also new

- `tools/validate_provenance.py`, `tools/validate_shots.py`, and `tools/validate_prompts.py`.
  Each ships a `--selftest`.
- `tools/check.sh` runs all eighteen checks. CI calls it.
- `install.sh` installs the tools to `~/.claude/shotkit-tools/`.
- Three or more `major` issues now force `REJECT`, and revision mode stops on `REJECT`.
- A worked two-round example at `skills/visual-asset-critic/examples/worked-run/`.

## Known gaps

- No approval log. `run.json` records what was built and reviewed, not who approved it.
- No migration tool for v2.0.0 output trees.
- No worked example for Veo, Seedance, or Hailuo in `one-shot-all-adapters/`.
- The explainer video is from v0.1.0 and still shows Runway/Sora. The demo GIF is from v2.0.0
  and shows the v2.0.0 output layout.

Full list in [`CHANGELOG.md`](https://github.com/whystrohm/shotkit/blob/main/CHANGELOG.md).
